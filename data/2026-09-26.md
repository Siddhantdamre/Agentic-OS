# DareX Engineering Log — 2026-09-26

## Summary of Changes

Today's focus was eliminating offline timeout latency in memory retrieval, making autonomy rules interactive with live PATCH APIs, transforming static showcases into operational hubs, and modernizing analytics dashboards with responsive layouts, refresh controls, and robust test suites.

---

### 1. Cognee Client Circuit Breaker (`bb49c6e`)

**Problem:**
- When Cognee was unconfigured or offline, calls to `searchCognee` and `rememberCognee` incurred slow connection timeouts on every retrieval turn, adding unnecessary latency to agent interactions.

**Changes Made:**
- In `services/workflows/src/memory/cognee-client.ts`:
  - Implemented an in-memory circuit breaker that detects repeated connection failures and trips open immediately to avoid latency penalties.
  - Added fast-path short-circuiting when the breaker is open, with automatic half-open health probing after cooldown.
- In `services/workflows/src/memory/retrieve.test.ts`:
  - Added unit test verifying circuit breaker trips and resets cleanly.

---

### 2. Interactive Autonomy Settings & Live Tier Controls (`f8da435`)

**Problem:**
- The Autonomy Settings page displayed static rule entries without the ability for tenant owners to modify approval requirements or adjust autonomy tiers (Tiers 1–4) in real time.
- Irreversible actions (such as refunds or permanent data deletion) required human approval guardrails at the database and API level.

**Changes Made:**
- In `apps/dashboard/app/api/settings/autonomy/route.ts`:
  - Added `PATCH` endpoint allowing tenant owners to update `requires_human_approval` and `autonomy_tier`.
  - Added strict protection preventing disabling human approval on irreversible actions (`reversibility === 'irreversible'`).
  - Added integer range validation (Tiers 1–4) and tenancy isolation via session-level RLS.
- In `apps/dashboard/components/settings/AutonomySettings.tsx`:
  - Made autonomy rules interactive with dropdown selectors for autonomy tiers and live toggle buttons for approval modes.
  - Added locked indicator preventing changes on irreversible rules with clear visual rationale.

### 3. Playbook Skills Operational Hub (`dffbc17`)

**Problem:**
- The `/skills` page previously displayed a static list of first-party playbooks without live connector health, assignment status, or direct execution actions.
- Several unused imports were lingering, and React hooks lacked proper memoization, causing lint warnings.

**Changes Made:**
- In `apps/dashboard/app/(dashboard)/skills/page.tsx`:
  - Rebuilt `/skills` as an operational playbook hub pulling live integration statuses and AI employee assignments.
  - Added real-time badge states (`Ready` vs `Needs Connector`), direct "Run in Ask AI" deeplinks with pre-filled prompts, and quick links to connector settings.
  - Added filter tabs (`All`, `Ready to Run`, `Needs Setup`) and search filtering by playbook name and capability.
  - Wrapped `loadData`, `isConnected`, and `getAuthorizedEmployees` in `useCallback` to satisfy `react-hooks/exhaustive-deps`.
  - Added accessible screen-reader announcements via `LiveRegion`.
- In `apps/dashboard/app/(dashboard)/skills/__tests__/page.test.tsx`:
  - Added comprehensive test suite asserting playbook rendering, connector readiness badges, employee assignment mapping, and search/tab filtering.
